# `_shared/` — helpers used by more than one skill

Not a skill. There is no `SKILL.md` here, so Claude Code never loads or triggers this
directory; it is a plain folder that `install.sh` mirrors to `~/.claude/skills/_shared/`
along with everything else under `skills/`.

Put something here when **two or more** skills use it. An asset used by exactly one skill
belongs in that skill's own folder.

**One folder per helper**, named after the helper, holding its script plus any files it
needs. Keeps the tree readable as more shared code lands here. A helper need not be a
script — `test_failure_modes/` is a pair of reference documents, shared for the same
reason the scripts are: two artifacts read it, so one copy has to be the source of truth.

| Folder | Used by | What it does |
|---|---|---|
| `review_diff/` — `review-diff.sh` | `handoff`, `rolling-plan`, `realign-plan`, `agent-brief` | Opens an editable side-by-side diff in VS Code (`code --wait --diff`), blocks until the tab closes, then writes the right (editable) pane to the destination. Emptying the right pane cancels (exit 2). Falls back to a plain write when the `code` CLI is absent. |
| `verify_logging_only/` — `verify-logging-only.sh` (+ `test-verify-logging-only.sh`) | `add-logging`, `@logging-plumber` (agent) | Proves an edit to a **Python** file changed only logging statements. Four channels: (1) **containment** — resolved log statements (receiver bound exactly once at module level to `logging.getLogger`, direct/imported/aliased, never shadowed; `self.logger`, loguru, structlog rejected as unresolvable) are deleted from both ASTs, suites pass-filled, trees compared, proving no non-log statement changed; (2) an **argument gate** on changed logs — walrus, await/yield, comprehensions, subscripts, f-string interpolation, and non-allowlisted calls exit `2` (pure re-levels are exempt: identical argument tuple, no new evaluation risk); (3) a **context-keyed inventory** that catches a log hoisted across a block boundary — a move *within* one suite is invisible by design, pinned as a LIMITATION harness case; (4) **docstring presence** — a log inserted above a docstring is a `+`-only diff that silently sets `__doc__` to `None`. Sanctions `import logging` + a module logger binding as setup, guarded so deleting an import that surviving code references stays UNSAFE. Exit `0` proves **containment, not behaviour** — argument purity is undecidable beyond literals, and tests/alerts/filters that observe logs live outside the file. Exit `0` contained · `1` unsafe, revert · `2` unprovable, revert + queue/hand-review. **Run `./test-verify-logging-only.sh` (35 cases) after any edit to the script.** |
| `verify_comments_only/` — `verify-comments-only.sh` (+ `test-verify-comments-only.sh`) | `comment-cleanup`, `@comment-janitor` (agent) | Proves an edit changed **only** comments and docstrings. Two-part, because either half alone is insufficient: (1) Python ASTs compared with docstring statements **dropped** (not blanked — blanking makes every full docstring *deletion* read as a code change), then a token stream with comments, docstrings and `pass` filtered out, which catches what an AST normalizes away (`1_000`→`1000`, collapsed implicit string concat, quote style); (2) every directive-shaped comment in the original must survive byte-identically and stay on its line where position matters — comments are not AST nodes, so an AST check alone passes while every comment is mangled. Also rejects an empty docstring left behind (ruff `D419` is on by default) and catches whitespace-level directive breakage such as `// go:build`, which silently stops being a build constraint. Falls back to `cloc --strip-comments` diffing outside Python — where exit `0` is **necessary, not sufficient**, since cloc lexes `#`/`//` inside heredocs and strings as comments. By policy it *accepts* an added docstring and a bare `pass` replacing a sole-statement docstring; `@comment-janitor`'s stricter "never add / never touch code" rules are its own prose, not enforced here. Exit `0` verified · `1` unsafe, revert · `2` unprovable, revert. **Run `./test-verify-comments-only.sh` (32 cases) after any edit to the script.** |

| `test_census/` — `test-census.sh` (+ `test-test-census.sh`) | `write-tests`, `@test-suite-auditor` (agent) | AST census of a pytest suite: **assertion-free** tests, **near-duplicate** bodies, and **declared-but-never-collected** tests. Discovers the repo's asserting helpers *mechanically* — every function whose body asserts, closed to a fixpoint over call edges — because a hardcoded call list is wrong by multiples on any repo with a custom idiom (sqlalchemy reads 6,804 assertion-free naively vs 1,359 once helpers resolve, and a report carrying the first number is checkably wrong). Separates four legitimate REVIEW classes from real findings: decorator-carried assertions, fixture-carried (`benchmark`), `catch_warnings` under `filterwarnings = error`, and single-call delegators. Near-duplicate fingerprints erase local *names* but **keep literals** and impose a 3-statement floor — blanking literals collapsed every single-assert test into one bucket (36 bogus groups on httpx); the cost is that genuinely identical 2-statement tests go undetected, pinned as a LIMITATION case. The collection-gap pass needs a dump taken with `-o addopts=""` or the repo's own `-q` prints per-file counts instead of node IDs, and it warns rather than reporting everything as uncollected. Exit `0` ran · `2` could not run. 0.198s over attrs' 585 tests. **Run `./test-test-census.sh` (28 cases) after any edit.** |
| `sabotage_check/` — `sabotage-check.sh` (+ `test-sabotage-check.sh`) | `write-tests`, `@test-suite-auditor` (agent) | Proves a suite actually **fails when the code it covers is broken** — the one thing coverage cannot tell you, since at Google 70% of real bugs were coupled to a mutant on already-covered lines. Deletes one statement (or negates one `if`/`while`) and runs a scoped test command. **Exit codes are deliberately INVERTED relative to the verifiers above: `0` = sabotage detected = the tests work; `1` = sabotage SURVIVED = the finding; `2` = could not run.** Statement deletion is the operator choice on purpose — it is 72% of Google's mutants and among the three most coupled to real faults, and mutmut 3 ships **no** statement-deletion operator at all, so this covers precisely the gap the tool leaves, with zero dependencies. Guardrails, all required before any edit: the target must be **tracked and clean in git**, a byte-exact backup is restored by an EXIT/INT/TERM trap and **verified by checksum** (a failed restore says so loudly and exits 2, never silently), the run is wall-clock capped by `SABOTAGE_TIMEOUT` (default 120s), and the suite must be **green before** sabotage or every verdict is noise. A **bound-name guard** downgrades to exit 2 when the deletion merely unbinds a name and the suite dies with `NameError`/`UnboundLocalError` — that proves the *code* broke, not that the tests check it, and an assertion-free smoke test would "detect" it equally loudly. Refuses to delete imports (a collection error is not a sabotage). Forces `NO_COLOR`/`PYTHON_COLORS=0` and strips ANSI before matching, because Python 3.13+ colourises tracebacks *inside* `NameError: name 'x'`. **Run `./test-sabotage-check.sh` (28 cases) after any edit.** |
| `test_failure_modes/` — `failure-modes.md`, `pytest-mechanics.md` | `write-tests`, `@test-suite-auditor` (agent) | Reference pair, not a script. `failure-modes.md` is the shared catalog of ~50 test defect classes in five families, each with a detection tag (`[static]` / `[static-config]` / `[runtime]` / `[judgment]`) and a severity (`false-pass` / `no-op` / `brittle` / `degraded`) so the skill knows what to avoid and the agent knows what to rank first — deliberately omitting advice a model already follows, which is ballast. `pytest-mechanics.md` carries the facts that cannot be inferred: the config gates that invalidate an audit if misread (the pytest 9 `[tool.pytest]` table that pytest 8 ignores silently, `addopts` poisoning every measurement, the single winning config file), the ruff `PT` verdict table splitting 10 zero-noise high-precision codes from the ~90%-style majority, a do-not-bother list (flake8-mock **breaks flake8**; PyNose is an unrunnable Kotlin plugin), the silent pytest footguns, the ordered detector stack with measured runtimes, and ground truth from nine elite repos. Both files carry their own sourcing caveats — notably that the most-cited "test smells cause flakiness" paper is **retracted**. |

Skills reference these by absolute installed path, e.g.:

```bash
~/.claude/skills/_shared/review_diff/review-diff.sh "$dest" "$proposed"
```

Because the path is shared, a change here changes every calling skill — grep for the
file name across `claude/skills/` before editing, and update the table when you add or
remove a helper.
